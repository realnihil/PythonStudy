## 1. 운영 환경 및 핵심 제약 조건 (반드시 유지)
- **OS / 실행 환경:** Windows, 주로 폐쇄망(내부망) PC에서도 동작해야 합니다.
- **단일 파일 휴대성:** 사용자가 **`code_tutor.py` 파일 1개만** 내부망 PC에 복사해 덮어쓰기하면 바로 동작해야 합니다.
  - 외부 이미지 파일에 의존하지 않습니다(국방과학연구소 로고도 Base64 PNG로 `code_tutor.py`에 직접 내장됨).
  - 무거운 외부 DB/임베딩 패키지(예: 벡터DB, `sentence-transformers`, `FAISS`)나 Node/React 빌드 파이프라인을 요구하지 않습니다.
- **서버 자동 교체:** `--serve` 실행 시 `code_hash`가 다르면 `/api/shutdown`으로 기존 `pythonw.exe` 서버를 종료하고 새 버전이 포트를 이어받습니다.
- **한글 경로 안전:** `_pick_directory_dialog`는 `base64` + ASCII JSON(`ensure_ascii=True`)으로 한글 경로를 주고받습니다.
- **주력 분석 대상 언어:** MATLAB(`.m`, 예: `EKF_JH_v3`, `Radar_OD` 등 수식/알고리즘 코드) 및 Python/JS/TS/C/C++.

## 2. 이미 구현·확정된 V1 기능 및 UI (유지할 사항)
- **3-패널 워크벤치 구조 (상단 글로벌 `<header>` 없음):**
  - 왼쪽/가운데/오른쪽 상단 첫 줄(`.pane-hdr`, `42px`) + 왼쪽·가운데 하단 바(`#footBar`)를 **웜 브론즈(다크 `#2a231c` / `#6e5a41`) · 웜 아이보리(라이트 `#f3ece1` / `#c8b69c`)** 톤과 2px 상단 포인트 라인으로 통일.
  - 가운데 패널 상단 양쪽 끝에 `◧` / `◨` 패널 접기/펼치기 버튼 배치(접혀 있을 때 강조 표시).
  - 오른쪽 `.tuttabs`(`🎓 1:1 튜터`, `🔎 변수 추적`, `🗺 흐름·구조`)도 가운데 `.tabs`(`① 개요`, `② 그래프`, `③ 코드보기`)와 동일한 강조 필 스타일 적용.
  - 하단 `#footBar`: 왼쪽에 ADD 로고 + `Code Tutor · 프로젝트명`, 오른쪽에 글자 크기 조절(`.fgrp`), 테마 전환(`☀/☾`), 도움말(`?`).
- **그래프·추적·성능 기능:**
  - `① 개요`: 1줄 KPI 카드, 제목 오른쪽 언어 배지, `파일 의존 관계` (`고립 파일 포함` 체크박스 기본 OFF, 한 줄 최대 노드 줄바꿈, `파일별 색` 범례 칩, `↗ 새 창으로` 분리 창 + 모달 fallback), 가운데 패널 전체 폭 사용.
  - `② 그래프`: 2줄 툴바, `◀`/`▶` + `Backspace` + 마우스 측면 버튼 뒤로/앞으로, `↗ 새 창` 양방향 동기화 창, 고유 SVG 마커 ID(`ah_<svg.id>`).
  - `🔎 변수 추적` & `🗺 흐름·구조`: 각각 `◀` / `▶` 히스토리 탐색 지원.
  - **크기 영속성:** 왼쪽·오른쪽 패널 가로 너비(`--sw`, `--tw`)와 `↗ 새 창` 팝업 창 크기(`gPopSz`, `ovPopSz`)를 `localStorage`(`ct_ui:*`)에 저장·복원.
  - **UI 반응성 최적화:** `#code` 줄 `content-visibility: auto`, `rowOf(l)` 캐싱, `applyVisibility`/`applyVar`/`renderSide(true)` 부분 갱신.
  - **LLM 상태 표시:** `use_llm && base_url && model` 모두 있을 때만 녹색(`AI: 모델명`) 표시, 미설정 시 주황색 경고(`URL 미설정`/`모델 미설정`), 저장 AI 해설도 없고 LLM도 미연결이면 `AI 해설` 버튼 비활성화.
- **아키텍처 결론:** 패널 전체(특히 오른쪽 튜터)를 별도 창으로 떼어내는 Dock/Undock은 단일 파일 구조에서 동기화 복잡도와 버그 위험이 커서 보류하고 현재 3-패널 + 그래프 새 창 구조를 유지하기로 합의함.

## 3. V2에서 추진할 목표: 논문 PDF / 경량 LLM-Wiki 연동
- **목적:** 코드 구조만 보고 해석할 때 부족한 도메인 맥락(수식 번호, 물리 변수 의미, 좌표계/알고리즘 가정 등)을 **관련 논문 자료를 참조해 설명 품질을 크게 높이기**.
- **합의된 설계 방향 (복잡도·속도 저하 최소화):**
  1. **무거운 벡터DB/임베딩 RAG 대신 경량 LLM-Wiki 방식 사용:**
     - 특정 폴더(예: 프로젝트 내 `papers/` 또는 사용자가 지정한 논문 폴더)에 `.pdf`, `.md`, `.txt` 자료를 넣어둠.
     - 프로젝트 분석 시(또는 `논문 인덱싱/요약` 버튼 클릭 시) **1회성으로** 텍스트를 추출·정리해 로컬 캐시(`.code_tutor_cache` 또는 요약 wiki)로 저장.
  2. **실시간 질문/해설 속도 유지:**
     - 질문 시마다 PDF 전체를 넣지 않고, 이미 캐시된 텍스트/요약 조각 중 **현재 함수명·변수명·키워드와 겹치는 2~3개 문단(약 1,000~1,500자)만 0.01초 내로 검색**해 LLM 프롬프트에 참고 근거로 주입.
  3. **PDF 파싱 호환성:**
     - Python 표준 라이브러리만으로는 PDF 압축 스트림 파싱이 어려우므로, `pypdf` / `pymupdf`(`fitz`)가 설치되어 있으면 PDF를 직접 읽고, 없는 환경에서는 `.txt`/`.md` 변환본을 바로 읽을 수 있게 graceful fallback 제공(필요 시 `wheels/`에 오프라인 wheel 추가 검토).
